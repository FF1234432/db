Test technique communication des résultats data : vulgarisation et impact

Les meilleures analyses ne valent rien si elles ne sont pas comprises et actionnées. En entretien, on évalue la capacité à communiquer des résultats data de manière simple et convaincante.

1Data storytelling : la structure narrative

Question discriminante

Qu est-ce que le data storytelling ? Quelle structure utilisez-vous ?

  • Data storytelling — combiner données, visualisations et narration pour convaincre et provoquer l action
  • Structure SCR — Situation (contexte), Complication (problème), Résolution (recommandation). Classique McKinsey
  • Structure piramide — commencer par la conclusion, puis les preuves. Pas le contraire
  • Exemple — 'Les ventes baissent de 15% (Situation). L analyse montre que c est concentré sur les clients < 2 ans (Complication). Voici 3 actions pour la rétention (Résolution)'
  • Une seule conclusion principale — une présentation avec 5 conclusions égales n est pas actionnée. Hiérarchiser

3Choisir le bon graphique pour convaincre

Question discriminante

Quels graphiques utilisez-vous selon le message à transmettre ?

  • Tendance dans le temps → ligne ou aire. Mettre en évidence le point d inflexion avec une annotation
  • Comparaison entre groupes → barres horizontales (si > 5 groupes) ou verticales. Trier par valeur
  • Composition → barres empilées à 100% si les proportions importent plus que les valeurs absolues
  • Distribution → boxplot ou violin plot pour montrer la variabilité, pas juste la moyenne
  • Corrélation → scatter plot avec ligne de régression. Annoter les outliers intéressants
  • Un seul KPI important → grande carte de score avec variation vs période précédente

4Éviter les biais cognitifs dans les visualisations

Question discriminante

Quels biais visuels fréquents évitez-vous dans vos dashboards ?

  • Axe Y tronqué — commencer l axe Y à 95 au lieu de 0 fait paraître une baisse de 1% comme énorme. Toujours partir de 0 pour les barres
  • Corrélation ≠ causalité — deux métriques qui montent ensemble ne sont pas forcément liées. Mentionner systématiquement
  • Cherry picking temporel — choisir une fenêtre qui montre une belle tendance. Montrer la période complète ou justifier le choix
  • Absence de contexte — '+10% de ventes' ne signifie rien sans la croissance moyenne du marché ou l objectif
  • Couleurs trompeuses — utiliser le rouge pour les valeurs 'bonnes' d une métrique où une hausse est mauvaise (coûts, délais)

5Structure d une bonne présentation data

Question discriminante

Quelle est la structure idéale d une présentation de résultats data ?

  • Slide 1 : Executive Summary — la conclusion en 3 bullets. Quelqu un qui lit seulement cette slide doit comprendre l essentiel
  • Slides 2-N : les preuves — un graphique, une idée par slide. Titre = le message principal (pas 'Évolution des ventes', mais 'Les ventes T3 sont en hausse de 12%')
  • Avant-dernière slide : recommandations — actions concrètes avec responsable et délai
  • Appendix — méthodologie, cavéats, données sources. Pour les questions techniques

6Rendre les résultats actionnables

Question discriminante

Qu est-ce qui différencie une analyse qui est actionnée d une analyse qui ne l est pas ?

  • Recommandation claire — 'nous recommandons d augmenter le budget email de 20%' plutôt que 'l email semble performant'
  • Responsable identifié — 'cette action est pour l équipe Marketing' pas 'quelqu un devrait faire...'
  • Délai proposé — 'à implémenter avant fin T3 pour capter la saison' crée une urgence légitime
  • Impact estimé — 'nous estimons +€50K de CA sur 6 mois' donne une base pour arbitrer les priorités
  • Simplicité — une analyse parfaite mais incomprise ne sera jamais actionnée. Simplifier avant de montrer
