Power Apps permet de creer des applications sans code. Entre un formulaire basique et une application robuste en production, l'ecart est considerable.

1Canvas apps et interface

Question discriminante

Difference entre une canvas app et une model-driven app ?

Canvas app = interface completement personnalisable. Model-driven app = generee depuis Dataverse, moins flexible mais plus rapide pour les CRUD standards.

  • Galleries — afficher des collections de donnees
  • Formulaires — saisie et modification
  • Navigate(), Back() — navigation entre ecrans

2Power Fx : le langage des formules

Question discriminante

Difference entre Patch() et SubmitForm() ? Quand utilisez-vous l'un ou l'autre ?

// Patch : mise a jour directe Patch(Commandes, LookUp(Commandes, ID = varID), {Statut: "Valide", DateValidation: Now()}) // Filter avec recherche Filter(Clients, StartsWith(Nom, txtRecherche.Text))
  • If() et Switch() — logique conditionnelle
  • Filter() et Search() — filtrer les collections
  • Collect() et ClearCollect() — gestion des collections locales
  • ForAll() — parcourir une collection

3Connecteurs et sources de donnees

Question discriminante

Vous construisez une app connectee a SharePoint et SQL Server. Quelles considerations de performance ?

Un profil confirme mentionne les limites de delegation : certaines fonctions Power Fx ne peuvent pas etre delegues a la source et chargent toutes les donnees localement (limite 500-2000 lignes par defaut).

Signal d'alerte : un profil qui ne connait pas la delegation va construire des apps qui plantent sur des listes SharePoint de plus de 2000 elements.

  • SharePoint, Dataverse, SQL Server, Excel Online
  • Connecteurs premium : SQL Server, Salesforce (licence premium)
  • Power Automate — declencher des flows depuis une app

4Gouvernance et ALM

Question discriminante

Comment gerez-vous les environnements Dev/Test/Prod dans Power Apps ?

  • Environments — Dev, Test, Prod dans le Power Platform admin center
  • Solutions — packager et deployer les apps
  • DLP policies — controler les connecteurs autorises

Power Apps enables building applications without code. Between a basic form and a robust production application, the gap is considerable.

1Canvas apps and interface

Discriminating question

Difference between a canvas app and a model-driven app?

Canvas app = fully customizable interface. Model-driven app = generated from Dataverse, less flexible but faster for standard CRUD operations.

  • Galleries — display data collections
  • Forms — input and editing
  • Navigate(), Back() — navigation between screens

2Power Fx: the formula language

Discriminating question

Difference between Patch() and SubmitForm()? When do you use one vs. the other?

// Patch : mise a jour directe Patch(Commandes, LookUp(Commandes, ID = varID), {Statut: "Valide", DateValidation: Now()}) // Filter avec recherche Filter(Clients, StartsWith(Nom, txtRecherche.Text))
  • If() and Switch() — conditional logic
  • Filter() and Search() — filtering collections
  • Collect() and ClearCollect() — local collection management
  • ForAll() — iterating over a collection

3Connectors and data sources

Discriminating question

You are building an app connected to SharePoint and SQL Server. What performance considerations apply?

An experienced profile will mention delegation limits: some Power Fx functions cannot be delegated to the data source and load all data locally (default limit of 500–2000 rows).

Warning sign: a profile who is not familiar with delegation will build apps that break on SharePoint lists with more than 2000 items.

  • SharePoint, Dataverse, SQL Server, Excel Online
  • Premium connectors: SQL Server, Salesforce (premium license required)
  • Power Automate — triggering flows from an app
