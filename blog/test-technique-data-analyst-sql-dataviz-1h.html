Test technique Data Analyst clé en main : SQL + dataviz en 1h

Ce test évalue un Data Analyst comme il travaille vraiment : d'abord interroger les données (SQL), puis les restituer clairement (dataviz). En une heure sur un même jeu de données, il donne une image fidèle du niveau. Corrigés et grille inclus — vous pouvez le donner tel quel.

La force de ce format est d'enchaîner les deux compétences clés du métier sur un cas unique : la rigueur SQL et la capacité à transformer un résultat en décision. Un bon analyste excelle sur les deux ; un profil déséquilibré se révèle vite.

1Le jeu de données

La consigne

Fournissez ces tables au candidat au début du test.

Un jeu e-commerce simple, commun aux deux parties. Le candidat l'utilise d'abord en SQL, puis pour concevoir une restitution.

commandes(id, client_id, produit_id, montant, date_commande, statut) clients(id, pays, date_inscription) produits(id, nom, categorie)

    2Partie 1 — SQL (30 min)

    La consigne

    Trois questions d'analyse à traduire en requêtes.

    Cette partie vérifie la rigueur SQL sur des questions réalistes : filtrer, joindre, agréger, et raisonner sur une tendance. Voici un exemple de corrigé pour la question centrale.

    -- Q3 : taux d'annulation par pays (exemple de corrige) SELECT c.pays, COUNT(*) FILTER (WHERE o.statut = 'annulee') * 1.0 / COUNT(*) AS taux_annulation FROM commandes o JOIN clients c ON c.id = o.client_id GROUP BY c.pays ORDER BY taux_annulation DESC;
    • Q1 : le CA mensuel des commandes payées (tendance).
    • Q2 : le top 5 des catégories par CA.
    • Q3 : le taux de commandes annulées par pays.

    3Partie 2 — Dataviz (30 min)

    La consigne

    Restituer les résultats pour un décideur non technique.

    Le candidat conçoit une restitution (sur l'outil de votre choix) à partir de ses résultats SQL. On n'évalue pas la beauté, mais la clarté du message et la pertinence des choix.

    • Choisit le bon type de visuel pour chaque message.
    • Hiérarchise l'information pour un décideur.
    • Sait tirer une conclusion actionnable, pas juste afficher des chiffres.
    • Sait dire ce que les données ne permettent pas de conclure.

    Signal d'alerte : ce que révèle ce test complet : un bon analyste est fort sur les deux parties. Attention au profil « SQL solide mais restitution confuse » (ou l'inverse) — le métier exige les deux.

    4La grille globale

    La consigne

    Notez les deux parties séparément, puis l'équilibre.

    Une bonne note demande d'être solide sur les deux dimensions. Un déséquilibre marqué est une information précieuse pour cadrer le poste.

    • SQL : justesse des requêtes et du raisonnement.
    • Dataviz : clarté du message et pertinence des choix.
    • Communication : capacité à conclure pour un décideur.
    • Équilibre entre les deux : le cœur du métier d'analyste.

    5Grille par niveau

    NiveauMaîtrise attendueSignal GONO-GO

    ConfirméSQL solide, restitution claireEnchaîne les deux partiesFort sur une partie, faible sur l'autre
    SeniorAnalyse + conclusion actionnableTransforme les données en décisionAffiche des chiffres sans conclure

    Turnkey Data Analyst technical test: SQL + dataviz in 1h

    This test assesses a Data Analyst as they really work: first query the data (SQL), then present it clearly (dataviz). In one hour on the same dataset, it gives a faithful picture of the level. Answers and grid included — you can give it as-is.

    Data Builder·July 2025·12 min read·Complete role test · Data Analyst · 1h

    2. Part 1 — SQL (30 min)

    4. The overall grid

    The strength of this format is chaining the role's two key skills on a single case: SQL rigour and the ability to turn a result into a decision. A good analyst excels at both; an unbalanced profile shows quickly.

    1The dataset

    The task

    Give these tables to the candidate at the start.

    A simple e-commerce dataset, shared by both parts. The candidate uses it first in SQL, then to design a presentation.

    commandes(id, client_id, produit_id, montant, date_commande, statut) clients(id, pays, date_inscription) produits(id, nom, categorie)

      2Part 1 — SQL (30 min)

      The task

      Three analysis questions to translate into queries.

      This part checks SQL rigour on realistic questions: filter, join, aggregate, and reason about a trend. Here's a sample answer for the central question.

      -- Q3 : taux d'annulation par pays (exemple de corrige) SELECT c.pays, COUNT(*) FILTER (WHERE o.statut = 'annulee') * 1.0 / COUNT(*) AS taux_annulation FROM commandes o JOIN clients c ON c.id = o.client_id GROUP BY c.pays ORDER BY taux_annulation DESC;
      • Q1: monthly revenue of paid orders (trend).
      • Q2: top 5 categories by revenue.
      • Q3: cancelled-order rate by country.

      3Part 2 — Dataviz (30 min)

      The task

      Present the results for a non-technical decision-maker.

      The candidate designs a presentation (in the tool of your choice) from their SQL results. We don't assess beauty, but message clarity and choice relevance.

      • Chooses the right visual type for each message.
      • Prioritizes information for a decision-maker.
      • Can draw an actionable conclusion, not just show numbers.
      • Can say what the data doesn't allow concluding.

      Warning signal : what this complete test reveals: a good analyst is strong on both parts. Beware the ‘solid SQL but confusing presentation’ profile (or the reverse) — the role requires both.

      4The overall grid

      The task

      Score both parts separately, then the balance.

      A good score requires being solid on both dimensions. A marked imbalance is valuable information for framing the role.

      • SQL: correctness of queries and reasoning.
      • Dataviz: message clarity and choice relevance.
      • Communication: ability to conclude for a decision-maker.
      • Balance between the two: the core of the analyst role.
