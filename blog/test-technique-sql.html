Test technique SQL : ce qu'on evalue vraiment en entretien data

SQL est la competence la plus universelle du monde data — et celle ou les entretiens sont le plus souvent mal calibres.

Data Builder·Juin 2025·9 min de lecture·Data Analyst · Analytics Engineer

Presque tous les candidats data disent maitriser SQL. Ce qui varie enormement, c'est ce que ca signifie reellement.

1Jointures

Question discriminante

Vous faites une LEFT JOIN entre commandes et clients. Combien de lignes si un client a passe 5 commandes ? Et si une commande n'a pas de client ?

Un bon profil repond immediatement : 5 lignes pour ce client, et une ligne avec NULL pour le client manquant. Il identifie spontanement le risque de duplication sur une cle non unique.

  • INNER / LEFT / FULL OUTER — maitriser les cas limites
  • SELF JOIN — hierarchies, comparaisons temporelles
  • CROSS JOIN — produit cartesien, dangereux sur grandes tables

Signal d'alerte : un candidat qui ne sait pas ce que produit une LEFT JOIN sur une cle non unique a droite est eliminatoire au niveau Confirme.

2Agregations avancees

Question discriminante

Calculez en une seule requete le CA total ET le CA pour les commandes > 100 euros, par region.

SELECT region, SUM(montant) AS ca_total, SUM(montant) FILTER (WHERE montant > 100) AS ca_sup_100 FROM commandes GROUP BY region
  • CASE WHEN dans SUM/COUNT — agregation conditionnelle universelle
  • FILTER — syntaxe plus propre (PostgreSQL, DuckDB, BigQuery)
  • HAVING vs WHERE — WHERE filtre avant agregation, HAVING apres
  • GROUPING SETS / ROLLUP / CUBE — multi-niveaux en une requete

3Window functions

Question discriminante

Calculez le CA cumule depuis le debut de l'annee pour chaque ligne, sans reduire le nombre de lignes.

SELECT date_vente, montant, SUM(montant) OVER ( PARTITION BY YEAR(date_vente) ORDER BY date_vente ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW ) AS ca_cumule FROM ventes
  • ROW_NUMBER / RANK / DENSE_RANK — classements avec ou sans ex-aequo
  • LAG / LEAD — valeur ligne precedente/suivante
  • QUALIFY — filtrer sur window function (BigQuery, Snowflake, DuckDB)

4Optimisation

Question discriminante

Votre requete sur 500M lignes prend 8 minutes. Que regardez-vous en premier ?

  • Plan d'execution — EXPLAIN ANALYZE (PostgreSQL), Query Plan (BigQuery)
  • Partitionnement — les filtres portent-ils sur la colonne de partition ?
  • SELECT * — eliminatoire en production niveau Senior

5Modelisation dimensionnelle

Question discriminante

Qu'est-ce qu'un schema en etoile ? Pourquoi est-il prefere au flocon de neige en analytique ?

  • Tables de faits vs dimensions
  • SCD type 2 — historisation des changements
  • Granularite — une ligne = une transaction

SQL technical interview: what we really assess in data hiring

SQL is the most universal data skill — and the one where interviews are most often poorly calibrated.

Almost all data candidates say they master SQL. What varies enormously is what that actually means.

1Joins

Discriminating question

You do a LEFT JOIN between orders and customers. How many rows if a customer placed 5 orders? And if an order has no customer?

A strong candidate answers immediately: 5 rows for that customer, and one row with NULL for the missing customer. They spontaneously identify the risk of duplication on a non-unique key.

  • INNER / LEFT / FULL OUTER — mastering edge cases
  • SELF JOIN — hierarchies, temporal comparisons
  • CROSS JOIN — cartesian product, dangerous on large tables

Red flag: a candidate who doesn't know what a LEFT JOIN on a non-unique right-side key produces is a dealbreaker at the Confirmed level.

2Advanced aggregations

Discriminating question

Calculate in a single query both total revenue AND revenue for orders > 100 euros, by region.

SELECT region, SUM(montant) AS ca_total, SUM(montant) FILTER (WHERE montant > 100) AS ca_sup_100 FROM commandes GROUP BY region
  • CASE WHEN inside SUM/COUNT — universal conditional aggregation
  • FILTER — cleaner syntax (PostgreSQL, DuckDB, BigQuery)
  • HAVING vs WHERE — WHERE filters before aggregation, HAVING after
  • GROUPING SETS / ROLLUP / CUBE — multi-level in a single query

3Window functions

Discriminating question

Calculate the cumulative revenue since the beginning of the year for each row, without reducing the number of rows.

SELECT date_vente, montant, SUM(montant) OVER ( PARTITION BY YEAR(date_vente) ORDER BY date_vente ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW ) AS ca_cumule FROM ventes
  • ROW_NUMBER / RANK / DENSE_RANK — rankings with or without ties
  • LAG / LEAD — previous/next row value
  • QUALIFY
